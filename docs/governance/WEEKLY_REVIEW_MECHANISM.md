# 风险台账周会机制

> 建立日期: 2026-04-11
> 最后更新: 2026-04-11

## 1. 会议目标

- 定期评审 P0/P1 风险状态
- 跟踪任务完成进度
- 识别和升级阻塞项
- 确保风险台账与实际状态同步

## 2. 会议安排

| 项目   | 内容                                                   |
| ------ | ------------------------------------------------------ |
| 频率   | 每周一 10:00-11:00                                     |
| 时长   | 60 分钟                                                |
| 参与人 | Tech Lead, SDK Core 工程师 A/B, QA, DevOps, 安全工程师 |
| 主持人 | Tech Lead (@sdk-arch)                                  |
| 记录人 | QA 工程师 (@qa-sdk)                                    |

## 3. 会议议程

### 3.1 开场 (5 分钟)

- 确认出席人员
- 回顾上周行动项完成情况

### 3.2 风险评审 (30 分钟)

#### P0 风险评审

- 逐项过审 `RISK_REGISTER.md` 中 P0 风险
- 确认状态更新（Open → 进行中 → Mitigated → Closed）
- 识别逾期风险，讨论升级方案

#### P1 风险评审

- 快速过审 P1 风险状态
- 关注即将到期项（截止日期前 7 天）

### 3.3 任务进度 (15 分钟)

- 过审 `SYSTEMIC_REFACTOR_EXECUTION_TASKBOARD_2026Q2.md`
- 确认本周完成任务
- 识别阻塞项和依赖

### 3.4 行动项确认 (10 分钟)

- 分配新行动项
- 确认责任人和截止时间
- 更新会议纪要

## 4. 输出物

每次会议需产出以下文档：

| 输出物         | 路径                                                   | 说明                                                   |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------ |
| 会议纪要       | `docs/governance/weekly-reviews/YYYY-WW.md`            | 记录决策、行动项                                       |
| 风险台账更新   | `docs/governance/RISK_REGISTER.md`                     | 同步状态变更                                           |
| 执行台账更新   | `docs/SYSTEMIC_REFACTOR_EXECUTION_TASKBOARD_2026Q2.md` | 同步任务进度                                           |
| 未完成任务统计 | `docs/SYSTEMIC_REFACTOR_EXECUTION_TASKBOARD_2026Q2.md` | 回填未完成任务总数与任务清单                           |
| T-U1 路径分布  | `docs/governance/weekly-reviews/YYYY-WW.md`            | 回填 `core/advanced/legacy` 本周新增与累计模块采用情况 |

### 未完成任务统计口径

- 统计来源：`SYSTEMIC_REFACTOR_EXECUTION_TASKBOARD_2026Q2.md` 的任务总表
- 计入口径：状态为`进行中`或`未开始`的任务
- 排除口径：状态为`已完成/✅ 已完成/Closed/Mitigated`的任务
- 会后要求：在周会纪要“会后状态回填”章节同步当周数量变化与主要增减原因

## 5. 升级机制

### 5.1 自动升级规则

| 条件                    | 升级目标            |
| ----------------------- | ------------------- |
| P0 任务逾期超过 3 天    | 架构周会 + 部门总监 |
| P1 任务逾期超过 7 天    | 架构周会            |
| 高危漏洞未在 SLA 内修复 | 安全周会            |
| 风险台账连续 2 周未更新 | Tech Lead           |

### 5.2 逾期风险处理流程

1. **识别**: 周会前自动扫描逾期项
2. **评估**: 讨论逾期原因和影响
3. **决策**: 确定是否延期、升级或重新分配
4. **记录**: 在风险台账更新决策和新的截止时间

## 6. 会前准备

### 主持人准备 (会议前 1 天)

- [ ] 运行 `pnpm quality:report` 生成质量报告
- [ ] 检查风险台账逾期项
- [ ] 检查执行台账逾期任务
- [ ] 准备上周行动项清单

### 参与人准备 (会议前 1 天)

- [ ] 更新负责任务的状态
- [ ] 准备阻塞项说明
- [ ] 提出需要讨论的问题

## 7. 会后跟进

### 记录人 (会议当天)

- [ ] 整理会议纪要
- [ ] 更新风险台账
- [ ] 更新执行台账
- [ ] 发送会议纪要邮件

### 行动项负责人

- [ ] 确认收到行动项
- [ ] 在截止时间前完成
- [ ] 更新相关文档
