# 02 · 端到端加密初始化

覆盖三件事：**本设备首次建立加密身份**（4S + cross-signing）、**在新设备上用恢复密钥还原**、**密钥备份的状态检查**。

> 本 fork 的加密后端是 Rust（`@matrix-org/matrix-sdk-crypto-wasm`）。`initLegacyCrypto()` 已废弃，**一律用 `initRustCrypto()`**。

---

## 三个必须理解的约束

在写代码之前，这三条决定了初始化的形状：

### 约束 1：加密要求 `userId` 与 `deviceId` 已知

`initRustCrypto()` 会在缺失时直接抛错：

```text
Cannot enable encryption on MatrixClient with unknown userId: ensure userId is passed in createClient().
Cannot enable encryption on MatrixClient with unknown deviceId: ensure deviceId is passed in createClient().
```

所以**不能**用"未认证 client + `loginRequest`"的路径来初始化加密——必须先拿到 `device_id`。

### 约束 2：默认拒绝"不加密的内存密钥库"

密钥库是 E2EE 的根。本 fork 加了两道默认拒绝（ISSUE-08b）：

| 情形                                               | 结果                                                                                                           |
| :------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| `useIndexedDB: true` + `storageKey`                | ✅ 加密的 IndexedDB 库                                                                                         |
| `useIndexedDB: false` + 无任何 key                 | ❌ 抛错：`Refusing to open unencrypted in-memory crypto store; ...`                                            |
| `useIndexedDB: false` + `allowInMemoryStore: true` | ⚠️ 内存库；且 `NODE_ENV=production` 时**再次拒绝**：`allowInMemoryStore is not permitted in production builds` |

结论：**生产环境必须从系统钥匙串派生 `storageKey`（32 字节）**，`allowInMemoryStore` 只能用于测试与临时会话。

### 约束 3：secret storage 的密钥靠回调交付，SDK 不替你持久化

`cryptoCallbacks.getSecretStorageKey` 负责"把恢复密钥交给 SDK"，`cacheSecretStorageKey` 负责"SDK 新建密钥时通知你保存"。SDK 本身**不落盘**恢复密钥——那是宿主的责任（钥匙串 / 用户抄写）。

## 场景 A：本设备首次建立加密身份

```typescript title="02a-e2ee-bootstrap.ts"
/**
 * 02a-e2ee-bootstrap.ts —— 为新设备建立 4S + cross-signing
 *
 * 运行（演示用，内存密钥库；生产请见 README 约束 2）：
 *   MATRIX_HOMESERVER=https://matrix.test \
 *   MATRIX_USER=alice MATRIX_PASSWORD=alice-secret \
 *   npx tsx 02a-e2ee-bootstrap.ts
 *
 * 已有会话时同样支持：
 *   MATRIX_ACCESS_TOKEN=syt_xxx MATRIX_USER_ID=@alice:matrix.test MATRIX_DEVICE_ID=ABCDEFGH tsx 02a-e2ee-bootstrap.ts
 */
import { AuthType, ClientEvent, createClient, type MatrixClient, SdkError, SyncState } from "@langkebo/matrix-js-sdk";

const HOMESERVER = process.env.MATRIX_HOMESERVER ?? "https://matrix.test";
const USER = process.env.MATRIX_USER ?? "alice";
const PASSWORD = process.env.MATRIX_PASSWORD ?? "alice-secret";

/**
 * 恢复密钥的内存缓存。
 *
 * 生产环境应替换为系统钥匙串读写（macOS Keychain / Windows DPAPI / libsecret）。
 * 类型参数写成 Uint8Array<ArrayBuffer> 是为了匹配 CryptoCallbacks 的签名。
 */
const secretStorageKeyCache = new Map<string, Uint8Array<ArrayBuffer>>();

/** 1) 登录并取得带 deviceId 的已认证 client —— E2EE 的硬前提。 */
async function connect(): Promise<{ client: MatrixClient; password: string }> {
    const token = process.env.MATRIX_ACCESS_TOKEN;
    const userId = process.env.MATRIX_USER_ID;
    const deviceId = process.env.MATRIX_DEVICE_ID;

    if (token && userId && deviceId) {
        return {
            client: createClient({ baseUrl: HOMESERVER, accessToken: token, userId, deviceId }),
            password: PASSWORD,
        };
    }

    const bootstrap = createClient({ baseUrl: HOMESERVER });
    const res = await bootstrap.loginRequest({
        type: "m.login.password",
        identifier: { type: "m.id.user", user: USER },
        password: PASSWORD,
        initial_device_display_name: "quickstart-02-e2ee",
    });
    console.log(`[login] ${res.user_id} device=${res.device_id}`);

    const client = createClient({
        baseUrl: HOMESERVER,
        accessToken: res.access_token,
        userId: res.user_id,
        deviceId: res.device_id,
        cryptoCallbacks: {
            // SDK 需要恢复密钥时回调本函数；返回 [keyId, privateKey] 或 null。
            getSecretStorageKey: async ({ keys }) => {
                for (const keyId of Object.keys(keys)) {
                    const privateKey = secretStorageKeyCache.get(keyId);
                    if (privateKey) return [keyId, privateKey];
                }
                return null;
            },
            // SDK 新建密钥时回调本函数 —— 宿主必须在这里持久化（钥匙串）。
            // _keyInfo 的类型是 SecretStorageKeyDescription，来自 `matrix-sdk-js/crypto` 子入口，
            // 这里用下划线前缀表示不使用，交给类型推断。
            cacheSecretStorageKey: (keyId, _keyInfo, key) => {
                secretStorageKeyCache.set(keyId, key);
                console.log(`[4s] 新密钥 ${keyId} 已缓存（生产环境请写入系统钥匙串）`);
            },
        },
    });
    return { client, password: PASSWORD };
}

/** 2) 初始化 Rust 加密后端。 */
async function initCrypto(client: MatrixClient): Promise<void> {
    await client.initRustCrypto({
        // 演示：内存密钥库，不需要钥匙串。生产改为 useIndexedDB: true + storageKey。
        useIndexedDB: false,
        allowInMemoryStore: true,
    });
    console.log("[crypto] Rust crypto 已初始化");
}

/** 3) 等待首次 sync —— cross-signing 相关请求依赖 account_data 已就绪。 */
async function waitForPrepared(client: MatrixClient): Promise<void> {
    await new Promise<void>((resolve) => {
        const onSync = (state: SyncState): void => {
            if (state === SyncState.Prepared) {
                client.off(ClientEvent.Sync, onSync);
                resolve();
            }
        };
        client.on(ClientEvent.Sync, onSync);
    });
    console.log("[sync] PREPARED");
}

/** 4) 建立 cross-signing + secret storage（4S）。 */
async function bootstrap(client: MatrixClient, password: string): Promise<void> {
    const crypto = client.getCrypto();
    if (!crypto) throw new Error("getCrypto() 返回 undefined —— initRustCrypto() 未成功执行");

    console.log(`[4s] 初始化前 ready=${await crypto.isSecretStorageReady()}`);

    // 4.1 生成恢复密钥。passphrase 由用户保管；返回对象里 encodedPrivateKey 是给用户抄写的形式。
    const recoveryKey = await crypto.createRecoveryKeyFromPassphrase(`quickstart-${Date.now()}`);
    if (recoveryKey.encodedPrivateKey) {
        console.log(`[4s] ⚠️ 恢复密钥（请立即抄写并妥善保管）：${recoveryKey.encodedPrivateKey}`);
    }

    // 4.2 建立 secret storage。setupNewSecretStorage=true 会新建默认密钥。
    await crypto.bootstrapSecretStorage({
        setupNewSecretStorage: true,
        createSecretStorageKey: async () => recoveryKey,
    });
    console.log(`[4s] secret storage 已建立，defaultKeyId=${await client.secretStorage.getDefaultKeyId()}`);

    // 4.3 建立 cross-signing 并上传公钥。上传需要 UIA（用户交互认证）。
    await crypto.bootstrapCrossSigning({
        authUploadDeviceSigningKeys: async (makeRequest) => {
            try {
                // 首次尝试不带 auth：服务端若不要求 UIA 就直接成功。
                return await makeRequest(null);
            } catch (err) {
                const e = err as { errcode?: string; data?: { session?: string } };
                if (e.errcode !== "M_UIA_REQUIRED") throw err;

                // 服务端要求 UIA：补上密码 + session 重试。
                console.log(`[uia] 服务端要求二次认证（session=${e.data?.session ?? "-"}）`);
                return await makeRequest({
                    type: AuthType.Password,
                    identifier: { type: "m.id.user", user: client.getUserId() ?? USER },
                    password,
                    session: e.data?.session ?? "",
                });
            }
        },
    });
    console.log("[xs] cross-signing 已建立并上传");
}

/** 5) 验证结果。 */
async function verify(client: MatrixClient): Promise<void> {
    const crypto = client.getCrypto();
    if (!crypto) throw new Error("crypto 不可用");

    const xsReady = await crypto.isCrossSigningReady();
    const ssReady = await crypto.isSecretStorageReady();
    const status = await crypto.getSecretStorageStatus();

    console.log(`[verify] crossSigningReady=${xsReady} secretStorageReady=${ssReady}`);
    console.log(`[verify] 4S defaultKeyId=${status.defaultKeyId ?? "-"} ready=${status.ready}`);
    console.log(
        `[verify] 私钥已存入 4S: master=${status.secretStorageKeyValidityMap["m.cross_signing.master"] ?? false} ` +
            `self_signing=${status.secretStorageKeyValidityMap["m.cross_signing.self_signing"] ?? false} ` +
            `user_signing=${status.secretStorageKeyValidityMap["m.cross_signing.user_signing"] ?? false}`,
    );

    // 本设备自己的密钥
    const own = await crypto.getOwnDeviceKeys();
    console.log(`[verify] 本机 ed25519=${own.ed25519.slice(0, 12)}… curve25519=${own.curve25519.slice(0, 12)}…`);

    // 密钥备份状态（未启用时为 null）
    const backup = await crypto.getKeyBackupInfo();
    console.log(`[verify] keyBackup=${backup ? `version=${backup.version}` : "未启用"}`);
}

async function main(): Promise<void> {
    const { client, password } = await connect();
    await initCrypto(client);

    const started = client.startClient({ initialSyncLimit: 20 });
    await waitForPrepared(client);

    await bootstrap(client, password);
    await verify(client);

    await started;
    client.stopClient();
}

main().catch((err: unknown) => {
    if (err instanceof SdkError) {
        console.error(`[fatal] ${err.name} code=${err.errorCode} status=${err.statusCode} msg=${err.message}`);
    } else {
        console.error("[fatal]", err);
    }
    process.exit(1);
});
```

## 场景 B：在新设备上用恢复密钥还原

新建一个设备（或清空本地密钥库）后，用上次抄写的恢复密钥把 cross-signing 私钥与房间密钥取回来。**这里的 `getSecretStorageKey` 直接返回恢复密钥，不需要密码。**

```typescript title="02b-e2ee-restore.ts"
/**
 * 02b-e2ee-restore.ts —— 用恢复密钥在新设备还原加密身份
 *
 * 运行：
 *   MATRIX_HOMESERVER=https://matrix.test \
 *   MATRIX_USER=alice MATRIX_PASSWORD=alice-secret \
 *   MATRIX_RECOVERY_KEY='EsT...' \
 *   npx tsx 02b-e2ee-restore.ts
 */
import { ClientEvent, createClient, type MatrixClient, SdkError, SyncState } from "@langkebo/matrix-js-sdk";
// 注意：decodeRecoveryKey 属于 crypto 子入口，不在根入口。
import { decodeRecoveryKey } from "@langkebo/matrix-js-sdk/crypto";

const HOMESERVER = process.env.MATRIX_HOMESERVER ?? "https://matrix.test";
const USER = process.env.MATRIX_USER ?? "alice";
const PASSWORD = process.env.MATRIX_PASSWORD ?? "alice-secret";
const RECOVERY_KEY = process.env.MATRIX_RECOVERY_KEY ?? "";

async function main(): Promise<void> {
    if (!RECOVERY_KEY) throw new Error("请通过 MATRIX_RECOVERY_KEY 提供恢复密钥");

    // 恢复密钥是 base58 + 校验和编码，需先解码成原始 key 字节。
    const privateKey = decodeRecoveryKey(RECOVERY_KEY);

    const bootstrap = createClient({ baseUrl: HOMESERVER });
    const res = await bootstrap.loginRequest({
        type: "m.login.password",
        identifier: { type: "m.id.user", user: USER },
        password: PASSWORD,
        initial_device_display_name: "quickstart-02-restore",
    });
    console.log(`[login] 新设备 device=${res.device_id}`);

    const client = createClient({
        baseUrl: HOMESERVER,
        accessToken: res.access_token,
        userId: res.user_id,
        deviceId: res.device_id,
        cryptoCallbacks: {
            // 关键差异：直接返回用户提供的恢复密钥，不做交互式询问。
            getSecretStorageKey: async ({ keys }) => {
                const firstKeyId = Object.keys(keys)[0];
                if (!firstKeyId) return null;
                return [firstKeyId, privateKey];
            },
        },
    });

    await client.initRustCrypto({ useIndexedDB: false, allowInMemoryStore: true });

    const crypto = client.getCrypto();
    if (!crypto) throw new Error("getCrypto() 返回 undefined");

    client.startClient({ initialSyncLimit: 20 });
    await waitForPrepared(client);

    // 1) 从 4S 拉取 cross-signing 私钥（bootstrapSecretStorage 在密钥已存在时不新建，只读取）。
    await crypto.bootstrapSecretStorage({});
    await crypto.bootstrapCrossSigning({});

    console.log(`[restore] crossSigningReady=${await crypto.isCrossSigningReady()}`);
    console.log(`[restore] secretStorageReady=${await crypto.isSecretStorageReady()}`);

    // 2) 从 4S 取回密钥备份的解密密钥，并启用备份。
    await crypto.loadSessionBackupPrivateKeyFromSecretStorage();
    const backupInfo = await crypto.getKeyBackupInfo();
    if (backupInfo) {
        const trust = await crypto.isKeyBackupTrusted(backupInfo);
        console.log(
            `[restore] backup version=${backupInfo.version ?? "-"} trusted=${trust.trusted} ` +
                `matchesDecryptionKey=${trust.matchesDecryptionKey}`,
        );
        const check = await crypto.checkKeyBackupAndEnable();
        console.log(`[restore] 备份已${check ? "启用" : "未启用"}`);
    } else {
        console.log("[restore] 服务端没有密钥备份");
    }

    client.stopClient();
}

async function waitForPrepared(client: MatrixClient): Promise<void> {
    await new Promise<void>((resolve) => {
        const onSync = (state: SyncState): void => {
            if (state === SyncState.Prepared) {
                client.off(ClientEvent.Sync, onSync);
                resolve();
            }
        };
        client.on(ClientEvent.Sync, onSync);
    });
}

main().catch((err: unknown) => {
    if (err instanceof SdkError) {
        console.error(`[fatal] ${err.name} code=${err.errorCode} status=${err.statusCode} msg=${err.message}`);
    } else {
        console.error("[fatal]", err);
    }
    process.exit(1);
});
```

## 场景 C：密钥备份与设备验证

初始化完成后的两个常见后续动作：

```typescript title="02c-e2ee-backup-and-verify.ts"
/**
 * 02c-e2ee-backup-and-verify.ts —— 启用密钥备份 + 发起设备验证
 * 前置：已完成场景 A 的 bootstrap（本文件只演示调用形状，需接入你自己的 client）
 */
import { AuthType, type MatrixClient, SdkError } from "@langkebo/matrix-js-sdk";
// 注意：VerificationRequestEvent 属于 crypto 子入口，不在根入口。
import { VerificationRequestEvent } from "@langkebo/matrix-js-sdk/crypto";

export async function enableKeyBackup(
    client: MatrixClient,
    password: string,
    userId: string,
): Promise<string | undefined> {
    const crypto = client.getCrypto();
    if (!crypto) throw new Error("crypto 不可用");

    // resetKeyBackup(auth?: AuthDict) 会丢弃旧备份、新建一个版本，并把解密密钥写入 4S。
    // ⚠️ 它只接收一个 AuthDict，没有 UIA 重试循环：若服务端要求 M_UIA_REQUIRED，
    //    需要用返回的 session 自行补一次带 session 的调用（或先在别处完成 UIA）。
    await crypto.resetKeyBackup({
        type: AuthType.Password,
        identifier: { type: "m.id.user", user: userId },
        password,
    });

    const info = await crypto.getKeyBackupInfo();
    if (!info) throw new Error("resetKeyBackup 之后仍无备份信息");

    const trust = await crypto.isKeyBackupTrusted(info);
    // KeyBackupInfo.version 是可选的，别假设它一定存在。
    console.log(`[backup] version=${info.version ?? "-"} trusted=${trust.trusted}`);
    return info.version;
}

export async function verifyOwnDevice(client: MatrixClient): Promise<void> {
    const crypto = client.getCrypto();
    if (!crypto) throw new Error("crypto 不可用");

    const userId = client.getUserId();
    const deviceId = client.getDeviceId();
    if (!userId || !deviceId) throw new Error("缺少 userId / deviceId");

    // 1) 发起验证（另一台已信任设备上会弹出确认）。
    const request = await crypto.requestDeviceVerification(userId, deviceId);
    console.log(
        `[verify] 验证已发起 txn=${request.transactionId ?? "(尚未分配)"} ` +
            `otherDevice=${request.otherDeviceId ?? "-"} phase=${request.phase}`,
    );

    // 2) 订阅状态变化。VerificationRequest 自身就是事件发射器，事件名只有 Change。
    request.on(VerificationRequestEvent.Change, () => {
        console.log(`[verify] phase=${request.phase} pending=${request.pending}`);
    });

    // 3) 验证完成后本设备可被信任；getDeviceVerificationStatus 此时返回 isVerified() === true。
    const status = await crypto.getDeviceVerificationStatus(userId, deviceId);
    console.log(`[verify] own device verified=${status?.isVerified() ?? false}`);
}

/** 遇到问题时统一打印可诊断字段。 */
export function reportCryptoError(err: unknown): void {
    if (err instanceof SdkError) {
        console.error(`[crypto-error] ${err.name} code=${err.errorCode} status=${err.statusCode} trace=${err.traceId}`);
    }
}
```

## 逐段说明

### 为什么 `isSecretStorageReady()` 一开始是 `false`

`bootstrapSecretStorage()` 只是**建立 4S 容器并写入密钥**。`isSecretStorageReady()` 的语义是"4S 里已经存有全部必需的私钥"——具体是 cross-signing 的三把私钥。因此正确的顺序是：

```text
initRustCrypto()
  └─► startClient() + 等到 PREPARED      ← 需要 account_data 就绪
        └─► bootstrapSecretStorage()      ← 建立 4S
              └─► bootstrapCrossSigning() ← 生成/导出 cross-signing 私钥并写入 4S
                    └─► isSecretStorageReady() === true
```

集成测试 `spec/integ/real-backend/cross-signing-secret-storage.spec.ts` 断言的正是这个顺序（场景 A 的代码结构与之对应）。

### `bootstrapSecretStorage` 是幂等的吗

取决于参数：

| 调用                                                                              | 行为                                                                               |
| :-------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| `bootstrapSecretStorage({})`                                                      | 4S 已存在 AES key 时**只读取**，不新建；不存在则因缺 `createSecretStorageKey` 抛错 |
| `bootstrapSecretStorage({ setupNewSecretStorage: true, createSecretStorageKey })` | **强制新建**默认密钥（会替换旧的）                                                 |
| `bootstrapSecretStorage({ setupNewKeyBackup: true, ... })`                        | 额外调用 `resetKeyBackup`，新建备份版本                                            |

**恢复场景务必用 `{}`**；用 `setupNewSecretStorage: true` 会把用户原来的恢复密钥作废。

### UIA 的处理是必需的

`/keys/device_signing/upload` 需要用户交互认证。服务端第一次会以 `M_UIA_REQUIRED` 拒绝，必须在 `authUploadDeviceSigningKeys` 里带上 `auth` 与 `session` 重试。**忽略这一步的典型症状**是：`bootstrapCrossSigning` 抛错、`isCrossSigningReady()` 永远 `false`，但 `bootstrapSecretStorage` 却是成功的。

### `storageKey` 的正确来源

```typescript
// 生产（浏览器/桌面）：从系统钥匙串取出 32 字节密钥
const storageKey = await readFromKeychain("tjg.matrix.crypto.store");
await client.initRustCrypto({ useIndexedDB: true, storageKey });

// 只有密钥派生自密码时才用 storagePassword（故意慢）
await client.initRustCrypto({ useIndexedDB: true, storagePassword: userProvidedPassphrase });

// 仅测试 / 临时会话
await client.initRustCrypto({ useIndexedDB: false, allowInMemoryStore: true });
```

## 常见陷阱

1. **忘了 `bootstrapCrossSigning`，只做了 `bootstrapSecretStorage`。** `isSecretStorageReady()` 一直 `false`，且新设备无法通过恢复密钥取回 cross-signing 私钥。
2. **恢复场景误用 `setupNewSecretStorage: true`。** 会作废用户手上的恢复密钥。
3. **恢复密钥没解码就传给 `getSecretStorageKey`。** 必须先用 `decodeRecoveryKey()` 从 base58 文本还原成字节。
4. **恢复密钥没有真正持久化。** `cacheSecretStorageKey` 只是回调通知，SDK 不落盘；宿主不写入钥匙串就等于丢密钥。
5. **在生产构建里用 `allowInMemoryStore`。** `NODE_ENV=production` 下会直接抛错（这是有意的最后一道防线）。
6. **`createClient` 时没传 `deviceId`。** `initRustCrypto` 直接抛错——E2EE 绑定的是"用户 × 设备"身份。
7. **在 `PREPARED` 之前就 bootstrap。** cross-signing 上传依赖 account_data 已同步，过早调用会拿到不完整的 4S 状态。
8. **`initRustCrypto` 重复调用。** 第二次会打一条 warn 后直接返回，**不会**重新初始化。需要换密钥库请重建 client。
